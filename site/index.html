No database, no daemon, no account. Markdown your agent reads at the start of a session, and updates at the end of one.

Because it lives in the repo, it travels the way code travels: through branches, pull requests, and whoever clones it next.

It does not run the model. It hands whoever arrives next the same story you had.

02 — Why the repo isn't enough

History tells you what changed. Never what you'd already ruled out.

Three commits. Not one of them says which approach lost, or why. So the next session reconstructs the story from scratch — and cheerfully proposes Thursday's rejected plan.

03 — What happened when we used it

Someone renamed one file. Three places in the docs quietly went stale. CI caught all three before the merge — including the ones written by the person who wrote the rule.

What this doesn't prove. Two people, two machines, two different agents, over eighteen hours. Beyond two people it is untested, and Fragment checks continuity — not whether your code is correct.
