# Glossary

For teammates who are not engineers. Open when you need it; nothing to memorize.

**If a term shows up in chat and is not here, ask for it to be added** — you are
almost certainly not the only one who was unsure.

## Process terms

| Term | What it means |
|---|---|
| **Fragment** | One self-contained piece of work. See [`HOW-WE-WORK.md`](HOW-WE-WORK.md) |
| **Repo** | The project folder plus its whole change history |
| **CI** | A robot that checks the rules on every change. Red means something broke a rule |
| **PR** | A proposed change, packaged for someone else to review before it lands |
| **Runbook** | Step-by-step instructions to operate something, written for someone who did not build it |
| **Frontmatter** | The small block at the top of a document saying who owns it and when it was last checked |

## This project

| Term | What it means |
|---|---|
| **Item** | One piece of feedback, from any of the three channels |
| **Channel** | Where an item came from: the in-app widget, the support inbox, or app-store reviews |
| **De-duplication** | Noticing that two items are the same complaint. It **marks** them; it never deletes one |
| **Routing** | Deciding which team an item goes to |
| **Replay** | Running the current rules over last month's real items to see what they would have done |
| **Overlap** | An item that genuinely belongs to two teams. Currently unresolved — see [`STATE.md`](STATE.md) |
